# Jana Address

Офлайн-сервис разбора адресов Казахстана для первого направления Jana Post Terricon Hackathon 2026. REST API, КАТО/OSM-справочник, интерфейс проверки и воспроизводимый массив адресов с ошибками.

## Актуальная версия

- Публичный репозиторий: [github.com/timyname/HACK-JANAadress](https://github.com/timyname/HACK-JANAadress)
- Публичная браузерная демонстрация: [jana-address-team-73.ablecorgi64.chatgpt.site](https://jana-address-team-73.ablecorgi64.chatgpt.site/?v=16)
- Основной локальный запуск: Docker Compose, `http://127.0.0.1:8080`
- Последняя локальная проверка: 20 октября 2026 года — полный Python-набор тестов, 49 frontend-тестов, сборка сайта и Docker health-check.

Репозиторий содержит исходный код, тесты, схемы, конфигурацию Docker и инструкции воспроизводимого запуска. Сгенерированная база `data/public/gazetteer.sqlite`, исходный OSM PBF, официальные материалы организаторов и локальные результаты проверок намеренно не публикуются в Git: база воспроизводится из открытых источников по инструкции [OPEN_DATA_RUNTIME.md](docs/OPEN_DATA_RUNTIME.md). Это исключает публикацию закрытых данных и файлов, превышающих обычные ограничения GitHub.

[Фактический статус и ограничения поставки](docs/research/DELIVERY_STATUS.md). Полноценный Python-сервис и демонстрационный интерфейс запускаются локально.

[Матрица приёмки](docs/research/RUNTIME_ACCEPTANCE_MATRIX.md) отделяет подтверждённые проверки от ещё не выполненных запусков и требований Docker/offline.

## Запуск

Требуется Python 3.12+. В Windows вместо `python` можно использовать абсолютный путь к установленному Python.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
# Подготовьте справочник командами из docs/research/OPEN_DATA_RUNTIME.md.
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m uvicorn jana.api:app --host 127.0.0.1 --port 8080 --no-access-log
```

Откройте http://127.0.0.1:8080. Сервис требует `data/public/gazetteer.sqlite`; при отсутствии артефакта он сообщает ошибку запуска, а не выдаёт результат без справочника.

## Docker

Первоначальная сборка требует сети для базового образа и Python-пакетов. Справочник должен быть подготовлен заранее. После сборки все runtime-данные находятся внутри образа.

```sh
docker compose build
docker compose up -d
curl http://127.0.0.1:8080/health/ready
```

Для машины жюри без сети передайте предварительно собранный образ:

```sh
docker save jana-address:local -o jana-address-image.tar
# На целевой машине:
docker load -i jana-address-image.tar
docker compose up -d --no-build
```

У `compose.yaml` отключено автоматическое скачивание образа. Пользовательская
bridge-сеть публикует UI только на `127.0.0.1`; IP masquerading отключён как
сетевой слой защиты. Поскольку Docker Desktop на macOS может не соблюдать этот
driver option для egress, `JANA_OFFLINE=1` дополнительно запрещает внешние
TCP/UDP-соединения в единственном runtime-процессе Python, разрешая только
loopback health/API. Это сохраняет доступ браузера там, где `internal: true`
подавляет опубликованный порт. Старт без заранее собранного/доставленного
образа не считается проверкой автономного запуска. Финальная сборка и холодный
запуск проверены на Docker Desktop для macOS; отдельный потоковый режим
дополнительно запускается с `--network none`.

## API

`POST /parse`, `/batch`, `/api/parse` и `/api/v1/parse` вызывают один обработчик. Поддерживаются `application/json` с массивом записей и `multipart/form-data` с одним файлом в поле `file`. Ответ — JSON-массив из 14 полей, без внутренней диагностики.

```json
[{"id":"demo","raw_address":"Астана, улица Сынақ, дом 12/3, кв 7"}]
```

Пример полностью синтетический. Сохраните собственный файл в `data/private/` или используйте генератор ниже.

```sh
curl -X POST http://127.0.0.1:8080/parse -H "Content-Type: application/json" --data-binary @output/corpus/test-1000/input.json
curl -X POST http://127.0.0.1:8080/parse -F "file=@output/corpus/test-1000/input.json"
```

Максимум 10 000 записей, 10 MiB HTTP body, 8 192 символа на адрес. Невалидный пакет отклоняется целиком с безопасным кодом и индексом. Неизвестные входные ключи игнорируются. ID, исходные строки, порядок и повторы сохраняются.

`GET /health/live` — процесс работает. `GET /health/ready` — справочник загружен. `/openapi.json` — машинное описание маршрутов. Swagger CDN не используется. `/internal/parse` отдаёт результаты вместе с происхождением полей для UI.

Адреса без явных маркеров улицы и дома, например
`Астана манглик ел 47 квартира 57`, проходят дополнительный поиск только
внутри уже подтверждённого города. Сначала проверяются точные нормализованные
варианты, затем RapidFuzz сравнивает строку с городским списком улиц с порогом
80% и минимальным отрывом 5 процентных пунктов от другого кандидата. Это мера
сходства строк, а не вероятность правильного адреса. Район добавляется только
после обычной проверки однозначности улицы и точной привязки дома в локальном
справочнике; при конфликте или неизвестном доме поле остаётся `null`.

## Большой локальный источник: потоковый CLI

Для длинного источника не нужен один HTTP-запрос на 50 000 или 500 000
строк. CLI читает локальный UTF-8 NDJSON: **один объект `id`/`raw_address`
на физическую строку**, не JSON-массив. По умолчанию обрабатывает порциями
по 250 записей (настройка 1..1000); справочник открывается один раз.
Следующая порция читается после обработки предыдущей. Это ограничивает
память входа/выхода, но не отменяет обработку каждой переданной записи.
Оптимальный размер пакета и пропускная способность требуют измерения.

```powershell
.\.venv\Scripts\python.exe tools/parse_stream.py --input data/private/addresses.ndjson --output output/parsed.json --gazetteer data/public/gazetteer.sqlite --batch-size 250
```

Нужен заранее подготовленный и проверенный справочник; CLI его не скачивает
и не пересобирает. Выход — обычный JSON-массив с ровно 14 полями на запись,
включая неизвестные адреса. Порядок, повторяющиеся ID и `raw_address`
сохраняются. Это стандартный формат, не расширенный `jana-enriched/v1`.

В stderr после каждой порции выводится JSON-событие с `processed`,
`no_flags`, `attention`, без адресов и ID. `attention` означает отсутствие
одного из province/city/street_name/house, confidence ниже 0.75 либо
предупреждение парсера. Отсутствие необязательного ЖК, квартиры или
подъезда само по себе не делает запись проблемной. Сумма двух групп равна
`processed`; общий размер файла заранее не пересчитывается. Финальное
событие `complete` появляется только после публикации результата.

Лимит одной физической строки — 256 KiB **включая перевод строки**;
`raw_address` сохраняет общий лимит 8192 символа. Пустой файл допустим,
пустые строки, BOM, не-UTF-8 и невалидный JSON отклоняются. Ошибка содержит
безопасный код и, где применимо, номер строки; вся выгрузка не публикуется
частично. Прогресс до ошибки означает обработанные порции, не готовый файл.

Результат сначала пишется во временный файл рядом с назначенным выходом,
затем публикуется атомарно. Существующий выход не заменяется без явного
`--overwrite`; вход и справочник запрещены в качестве выхода, в том числе
через существующие symlink/hardlink-алиасы. При ошибке обработки или Ctrl+C
до публикации старый выход сохраняется; программа пытается удалить свой
временный файл, не маскируя исходную ошибку. Режим без перезаписи требует
поддержки hardlink файловой системой (локальные NTFS/Linux); если её нет,
команда безопасно завершается ошибкой. Блокировка файла, SIGKILL или
отключение питания могут оставить временный файл. Если удаление его
дополнительного имени не удалось уже после атомарной публикации,
полный результат существует, но команда сообщает `IO_ERROR`, а не
`complete`: нужно проверить выход и оставшийся временный файл.

Коды завершения: 0 — успех, 2 — вход/аргументы/конфликт пути,
1 — I/O/парсер/справочник, 130 — Ctrl+C. Stdout не содержит результатов.
Модуль `jana.streaming` также предоставляет ограниченный итератор порций
для произвольного iterable и writer для бинарного NDJSON-потока.

CLI включён в Dockerfile, например после сборки образа:

```sh
docker run --rm --network none --mount type=bind,src=/absolute/input-dir,dst=/input,readonly --mount type=bind,src=/absolute/output-dir,dst=/output jana-address:local python /app/tools/parse_stream.py --input /input/addresses.ndjson --output /output/parsed.json --gazetteer /app/data/public/gazetteer.sqlite
```

Каталог выхода должен разрешать запись пользователю контейнера UID 10001.
Это инструкция для будущей контейнерной проверки, **не подтверждение
выполненного Docker-прогона** на текущем хосте. Большой источник и временный
выход остаются локальными; текущий HTTP API и облачный preview этим не меняются.

## Проверка руками

1. В интерфейсе убедитесь, что отображается «сервер подключён» и режим `API`. Статический облачный preview показывает отдельный режим браузера.
2. Нажмите «Демо-пакет», откройте строку и сравните исходник с полями. Проверьте дробный дом, квартиру, подъезд и этаж.
3. Загрузите `output/corpus/test-1000/input.json`. Переключите «На проверку» — порог confidence ниже 0.75.
4. Проверьте бейджи «Из текста», «По справочнику» и «Эвристика». Confidence — рабочая эвристика, не вероятность безошибочного адреса.
5. Исправьте поле и сохраните. Его бейдж станет «Правка оператора». Исходная строка остаётся неизменной.
6. «Результат API» скачивает первоначальный результат. «С правками» — отдельную исправленную версию в том же публичном формате.
7. Сверьте выбранные записи с `manual-review.json` по инструкции `docs/research/SYNTHETIC_CORPUS.md`. Эталонные ответы нельзя поправлять под текущий парсер.

## Данные и измерения

Синтетический корпус проверяет известные типы ошибок и имеет независимые ожидаемые ответы. Он не заменяет реальные скрытые данные жюри. Географические справочники строятся из открытых КАТО и OSM; лицензии и происхождение описаны в `data/public/` и `docs/research/OPEN_DATA_RUNTIME.md`.

```powershell
.\.venv\Scripts\python.exe tools/verify_gazetteer.py --db data/public/gazetteer.sqlite --manifest data/public/source-manifest.json --report output/gazetteer-verification.json
.\.venv\Scripts\python.exe tools/synthetic_corpus.py generate --config configs/corpus/base.json --profile configs/corpus/dev-10000.json --out output/corpus/dev-10000
.\.venv\Scripts\python.exe tools/synthetic_corpus.py generate --config configs/corpus/base.json --profile configs/corpus/test-1000.json --out output/corpus/test-1000
.\.venv\Scripts\python.exe tools/benchmark.py --input output/corpus/test-1000/input.json --report output/benchmark.json --predicted output/parser/test-1000.json
.\.venv\Scripts\python.exe tools/evaluate.py --expected output/corpus/test-1000/expected.json --predicted output/parser/test-1000.json --oracle output/corpus/test-1000/oracle.jsonl --out output/parser/metrics.json
.\.venv\Scripts\python.exe tools/public_corpus.py --count 1000 --out output/public-corpus
.\.venv\Scripts\python.exe tools/check_offline.py --input output/corpus/smoke-32/input.json
.\.venv\Scripts\python.exe -m pytest
npm test
npm run build
```

Проверку `verify_gazetteer.py` выполняйте только на завершённом неизменяемом каталоге. Она проверяет структуру, целостность и совпадение metadata с manifest, записывает SHA-256, размеры и покрытие полей; успешный результат не доказывает полноту или географическую точность.

Benchmark измеряет HTTP-запрос до полного получения ответа. Норматив: 1000 записей не более 300 секунд; startup Docker не более 180 секунд. Время инициализации Python в health или после проверки базы не является временем Docker startup. Метрика 60/25/15 в локальном evaluator — приближение; точное совпадение с закрытым скриптом жюри не заявляется.

`output/public-corpus/input.json` — дополнительный массив из реальных открытых OSM-компонентов с искусственными перестановками, склейками и опечатками. Это не клиентские адреса и не реальные пользовательские ошибки. В `manifest.json` сохранены происхождение, число различных точек, хеши и ограничения; `oracle.jsonl` связывает строку с OSM-объектом. Административные значения этого набора могут использовать те же пространственные привязки, что и движок, поэтому они не являются независимой проверкой географической точности.

## Документы и организация

- `docs/research/JANA_ADDRESS_MASTER_BLUEPRINT.md` — развернутое досье, критерии жюри и мастер-промпты.
- `docs/superpowers/plans/2026-10-16-runtime-delivery.md` — текущие решения, границы модулей и распределение агентов.
- `docs/contracts/sample-contract.md` — контракт JSON.
- `docs/source/JanaAddress_TZ_final_v4.docx` и `data/private/official/` — исходный ТЗ и samples, только локально.
- JanaMen относится ко второму направлению и не включён в проект.

HTTP-загрузки не записываются на диск; потоковый CLI явно читает указанный
локальный файл и записывает результат с временным файлом рядом с ним.
Пакетные адреса не отправляются внешним геокодерам. Полный сервис предназначен
для локальной/ограниченной рабочей среды. В публичном облачном preview работает
браузерная демонстрация без локального SQLite-справочника; полный справочник,
REST API и Docker-runtime запускаются локально по инструкциям выше.
